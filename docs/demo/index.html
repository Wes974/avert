Tester Avert

Deux pages piégées, volontairement. Ouvrez-les dans Safari sur l'iPhone où Avert est installé : l'extension doit réagir sur chacune.

Avant de commencer

1
Installez Avert depuis TestFlight, puis ouvrez l'app une fois.
2
Activez l'extension : Réglages → Applications → Safari → Extensions → Avert. Mettez-la sur Autoriser pour tous les sites — sinon Safari redemande à chaque page et l'extension ne voit rien.
3
Si vous venez de mettre l'app à jour, fermez complètement Safari (glissez-le hors du sélecteur d'apps) avant de tester : un onglet déjà ouvert continue d'exécuter l'ancienne version de l'extension.

Test 1 — l'avertissement simple

Une page de connexion quelconque, qui envoie le mot de passe vers un autre serveur et cache un second champ. Aucune marque n'est en jeu : Avert doit afficher un bandeau en haut de la page, sans bloquer.

attendu : bandeau

Ouvrir le test 1

Test 2 — l'alerte forte

La même chose, mais la page affiche le logo de « Banque Démo » — une banque qui n'existe pas, inventée pour ce test — alors qu'elle est hébergée ailleurs que sur le domaine de cette marque. Avert reconnaît le logo au pixel près, constate que l'adresse ne correspond pas, et doit afficher un écran d'avertissement plein écran qui nomme « Banque Démo ».

attendu : écran plein

Ouvrir le test 2

Si rien ne se passe

  • L'extension est-elle sur Autoriser pour ce site ? (icône ᴀA dans la barre d'adresse → Gérer les extensions)
  • Safari a-t-il été relancé après l'installation ?
  • Sur le test 2, un bandeau au lieu de l'écran plein signifie que le logo n'a pas été reconnu — c'est une information utile, signalez-la.

Ce qui est envoyé pendant ce test

Rien. Les deux formulaires sont désactivés et pointent vers un domaine en .invalid, que la norme garantit non résoluble. Avert analyse les pages sur l'appareil et n'émet aucune requête réseau. Détail.
